# Передача контекста

## Сейчас

M0 и M1 завершены. На сборке `native-fdc87ae-52b423df4a8a` добавлен реестр до восьми одиночных сундуков: сервер читает физические слоты каждые 20 тиков и вычисляет нужды без исторических остатков M1. Проверены два сундука, добавление, изъятие, конфликт метки, отзыв, дубликат, повреждённый реестр, разрушение сундука и перезапуск без изменения снимка M1 (`target/m2-smoke/warehouses.json`). Обычный житель прошёл около семи блоков с запада и доставил одно бревно (`nav-acceptance.json` в той же папке). Пилот остаётся одноразовым; полный сундук, отзыв доставки и перезапуск без повтора проверены на предыдущей сборке `b6e7e04a5b18` (`recovery-verified.json`).

## Следующие действия

M2 ещё не завершён. Реестр пока только читает физический склад; доставка использует отдельное разрешение пилота. Нужны ограниченная запись и сверка незавершённых переносов. В закреплённой ревизии Horizon нет атомарной сохраняемой операции между блоком, экипировкой жителя и сундуком: текущий пилот fail-closed, но авария между раздельными записями может потерять груз. Сначала нужен журналированный идемпотентный перенос и тесты отказов, затем лесоруб: добыча только через `native_machine_destroy_block(..., collect = true)` с сохранением фактического лута.
