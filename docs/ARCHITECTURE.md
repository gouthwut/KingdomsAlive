# Архитектура

Сборка M0 использует каталог `mixins/kingdoms_alive/` с манифестом и Rust-обработчиком. Первые модули M1 лежат в `src/` и проверяются независимо от игры. Остальные границы вводятся по мере появления механик.

| Граница | Ответственность |
| --- | --- |
| settlements, citizens | Состояние мира мода, стабильные ключи поселений и жителей. |
| ai, simulation | Планирование по нуждам, состояния заданий, бюджет тика, переключение режимов. |
| economy | Склад, резервы, производство, переносимый груз и расход. |
| construction | Чертежи, проверка участка, блоки очереди и подтверждение применения. |
| contracts | Заказы, принятие, проверка поставки, награды и репутация. |
| horizon | Хуки, снимки мира, проверка возможности действия и вызов движка. |
| persistence, diagnostics | Сохранение по миру, миграции, журнал, длительность тиков и объём очередей. |

На серверном тике адаптер собирает нужный снимок мира. Правила симуляции выдают намерение, адаптер перепроверяет его, выполняет действие и подтверждает результат в состоянии мода. Клиент отображает результат и отправляет намерения игрока.

Модель хранит ключ измерения и координаты, а для жителей — UUID. Ссылки движка берутся на время одного хука. Реестр активных поселений обновляется событиями загрузки чанков. Два режима разделяют один учёт операций и переключаются на границе задачи с явным переносом или возвратом груза.

Хранилище M1 пишет `kingdoms_alive.json` в каталог мира. Формат содержит версию схемы. При ошибке чтения старый файл сохраняется, запись приостанавливается. Новый снимок записывается в отдельный временный файл в том же каталоге, сбрасывается на диск и заменяет старый. Адаптер Horizon должен выполнять записи последовательно на серверном потоке. Для строительства и заказов с побочными эффектами в игре потребуется журнал намерений и восстановления.
