# Horizon API и совместимость

Цель M0 — Minecraft: Java Edition 26.3 в Horizon Nightly `nightly-2026-11-08-fdc87ae`. Эта ревизия содержит Native Hooks API 411. Установленный лаунчер 0.2.57 собрал план с Horizon Mixins 0.6.0, ревизия `5a64af938ec86b00d53d16a408aabc0038fb3e57`. Точные версии также в [compatibility.json](../compatibility.json).

`.hnmod` содержит Rust-исходники, TOML и метаданные. Лаунчер компилирует их вместе с Horizon для выбранного профиля. `hook_version = 1` относится к сигнатуре одного хука. Для M2 минимум нумерованных API — 382 из-за экипировки. Пилот использует также ещё не пронумерованные помощники и внутренние методы конкретной ревизии. ## Физические контейнеры и доставка M2

| Возможность | Что подтверждает исходник ревизии |
| --- | --- |
| Слоты и вместимость | `native_container_slots` возвращает слоты и стеки, включая пустые слоты и обе половины двойного сундука. Возвращает `None` для недоступного контейнера или измерения. Метод документирован как API 48, но отсутствует в списке помощников `native-hooks.json`. `native_insert_item` вставляет по правилам воронки и возвращает остаток. `native_extract_item` извлекает стек из слота. `native_move_items` переносит предметы только между блоками-контейнерами. |
| Экипировка жителя | `native_living_equipment` и `native_living_set_equipment` API 382 читают и меняют экипировку. Движок сериализует `equipment.offhand` в NBT. Основную руку меняют ванильные торговые и социальные действия жителя. Общего вызова переноса между экипировкой и сундуком в этой ревизии нет. |
| Сохранение | Сундук и житель записываются в разные хранилища чанков. Событие `world_saved` сообщает о режиме записи. При обычном автосохранении запись асинхронна. Пилот использует внутренний `save_entities(true)` с ожиданием очереди записи перед вставкой в сундук. Сквозной транзакции нет. |
| Разрушение | При обычном разрушении движок удаляет блок-сущность, выбрасывает содержимое и закрывает открытое меню. Состояние и метка сундука перепроверяются перед действием. Пилот читает метку через внутренний `block_entity_nbt`, используемый командой `/data`. |
| Открытие | `container_opened` сообщает игрока, тип и позицию до открытия, допускает отмену. `player_container_open` и `player_container_close` дают UUID, измерение и позицию для жизненного цикла меню. |
| Кто изменил слоты | Фрагменты `inventory_click` и `inventory_drag` дают UUID и окно **до** применения ввода. `menu_clicked` относится к меню мода, `inventory_move_item` — к автоматизации. Подтверждённого события с исполнителем и фактической разницей слотов обычного сундука не найдено. Связка событий открытия и попытки клика годится для диагностики, персональное наказание требует подтверждённой транзакции. |

В прежнем интегрированном прогоне проверены путь обычного жителя, вторая рука, чтение и вставка в одиночный сундук, его обычное меню и изъятие игроком, сохранение, перезапуск и выпадение содержимого при разрушении. В восстановлении на `native-fdc87ae-b6e7e04a5b18` повторно проверены отсутствие разрешения, полный сундук, отзыв активной задачи, доставка и перезапуск без повтора; навигация с расстояния в новом прогоне завершилась тайм-аутом. ## Подтверждённый цикл лесоруба

На `native-fdc87ae-acd650484d83` в интегрированном сервере проверен `native_machine_destroy_block(source, None, true)`: два дубовых блока удалены, фактический лут передан жителю, затем в сундук, заранее груз не выдавался. Только стандартный лут одного дубового бревна допускается в перенос; при другом луте он выбрасывается на месте подтверждённо удалённого источника, задача удерживается. Сначала проверяется удаление источника, чтобы не породить копию при отказе замены блока.

Внутренний `save_level(true)` (`game.rs:15460–15475`) сохраняет изменённые чанки и сущности текущего измерения и ждёт `save.flush()`. Это подтвердило обычное сохранение добычи и доставки, **не** сквозную аварийную транзакцию. По исходнику `ServerTickStart` предшествует `update_world`, а `chunk_load` вызывается до присоединения сохранённых сущностей (`native_hooks.rs:8422–8424`). `WorldOpenReady` идёт после `settle_spawn`, где чанки уже загружаются. Нельзя считать эти события готовой общей границей безопасного восстановления двух объектов. Требуются охрана доступа и дополнительные проверки порядка загрузки.

Проверены заполненный склад, отзыв запроса, разрушение сундука во время переноски, отказ повторного адреса и удержание незавершённого груза при перезапуске. Инъекция сбоев и выгрузка чанка не проверены. Журнал пока только предотвращает слепой повтор. [Протокол следующего шага](M2_RECOVERY.md).

## Проверенный кодек свидетельства recovery

На той же ревизии `fdc87aecdbd116bf1e08adcd062fcbaea8c2e2ca` интегратор прочитал публичные исходники:

- [items.rs:332–338](https://github.com/horizon-rust/horizon/blob/fdc87aecdbd116bf1e08adcd062fcbaea8c2e2ca/crates/horizon-items/src/items.rs#L332): ItemStack содержит item/count/damage/extra, без derive Serialize. [item_nbt.rs:7–54](https://github.com/horizon-rust/horizon/blob/fdc87aecdbd116bf1e08adcd062fcbaea8c2e2ca/crates/horizon-items/src/item_nbt.rs#L7) даёт item_to_nbt/item_from_nbt. Декодер ограничивает count 1..=99, вне диапазона default=1; нельзя считать любой runtime-стек обратимым.
- [item_data.rs:748–801](https://github.com/horizon-rust/horizon/blob/fdc87aecdbd116bf1e08adcd062fcbaea8c2e2ca/crates/horizon-items/src/item_data.rs#L748): контекстно-независимый encode_components отличается от варианта с прототипами items. Runtime wire/выбранный элемент bundle исключены из равенства и сохранения; это не гарантия побайтного снимка runtime-структуры.
- [nbt.rs:437–495,678–688](https://github.com/horizon-rust/horizon/blob/fdc87aecdbd116bf1e08adcd062fcbaea8c2e2ca/crates/horizon-world/src/nbt.rs#L678): write_network сохраняет типы NBT и UTF-16, отказывает слишком длинным строкам; read_network нормализует отрицательный ноль float. `loot_codec.rs` проверяет обратное чтение Tag и ItemStack и отказывает при расхождении.
- [scoreboard.rs:36–72](https://github.com/horizon-rust/horizon/blob/fdc87aecdbd116bf1e08adcd062fcbaea8c2e2ca/crates/horizon-client-core/src/scoreboard.rs#L36): tag_to_json превращает Byte в bool и теряет типы NBT/часть UTF-16, поэтому для квитанции **не используется**. JSON хранит массивы исходных типизированных NBT-байтов, не перевод компонентов в обычный JSON.
- [native_machines.rs:51–61](https://github.com/horizon-rust/horizon/blob/fdc87aecdbd116bf1e08adcd062fcbaea8c2e2ca/crates/horizon-client/src/game/native_machines.rs#L51): destroy_block предшествует возврату drops. Новой атомарной операции не найдено; это подтверждает окно, не доказывает отсутствия альтернатив во всём движке.

Три теста настоящего кодека прошли отдельно от Cargo ядра через tools/check_loot_codec.py. Запись фактического результата подключена, но новые мутации лесоруба выключены. На `native-fdc87ae-340eb0689559` проверены только отказ новых мутаций, синтетический pending после двух открытий и сохранение .tmp при отказе. Аварийная сохранность, доступ игроков/ванили до сверки и выгрузка чанков не подтверждены.
